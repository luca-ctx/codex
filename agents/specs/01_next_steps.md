We need to figure out a good way to benchmark the end-to-end capabilities of this stack (the codex agent scaffold + our custom tools).

Unfortunately we have a catch-22 situation: you, as the current version of codex, cant evaluate some work that is beyond your capability to understand. For example, if we are trying to get codex to be able to evaluate a website as a QA agent, its pretty hard for you to know if its working because you yourself aren't great at it yet.

So we should come up with some good ways to benchmark the capabilities in a way that YOU can evaluate it. For example, you as codex should be able to make an exec plan, try a new feature idea that you think could work, then go and make the code changes, then do a debug build, then invoke the tool yourself, tell it "go do XYZ" (where XYZ is something you cannot already do but its a targeted capability) and then we have some way of grading it.

The grader could be something like we have a magic differ command that compares a figma screenshot with a playwright screenshot and counts how many pixels are off. If we just throw you at it right now, you might get it mostly right, but be like 15% off or 27m pixels off or whatever. But if you make some change that adds new prompting or capabilities with the Figma API and suddenly the new attempt results in 0% off or 1% off, you know that it is working.

Another one could be like you invoke a grader to evaluate on a scale of 1 - 10 how good the design is.

Another one could be like you want to create all these tools and capabilities and operational strategies and then invoke codex with an empty repo and a highly underspecified prompt, something like "build an AI lawyer business". The agent should know how to go off for a long time, do lots of industry research and come back with a market strategy document, complete with what all systems will be in place, how to wedge in and grow, etc. Once its done, it can ping the human for a review. Once the human approves the document, the agent should be able to one-shot go and build the whole thing (all the while, invoking sub-agents, doing code reviews, doing builds, etc). The agent can always ping the human to ask for things like "hey im ready to deploy to supabase, can you please use your debit card to create a Team account there and put the secrets in Infisical for me". but otherwise it does all of the hard stuff autonomously. When its finally done building everything and its ready to deploy to production, we have an agent independently review it and give it a rating. It should be complete and ready to go without issues. Even more, we could hook it up to publish the app on something like BetaTesting.com, we can provision it a credit, and it can collect usage data from real customers who can find bugs. A great agent should be able to one-shot something that doesnt really have many bugs at all, but if the real users find any things, the agent can autonomously fix them.
